Character Locomotion + Jump

Extending a walk/run character with a proper jump: rise, fall, and land, driven automatically by the player controller in Play mode.

Builds on the FBX Idle/Walk/Run setup · adds an air state machine keyed on IsGrounded / IsFalling / VerticalSpeed

What you'll build

A character whose animation graph blends Idle → Walk → Run on the ground and switches to Jump → Fall → Land in the air. You press Space to jump; the controller launches the capsule and the graph plays the air animations, returning to locomotion on landing — no scripting required.

The core idea. The player controller already reports its physical state every frame as animation parameters. For jumps the three that matter are IsGrounded (bool), IsFalling (bool) and VerticalSpeed (float, +up / −down). You add a few air states to the graph and wire transitions that compare those parameters. The engine sets them; your graph reacts.

Prerequisites

You should already have a working Idle / Walk / Run character (see the Animated Character Setup guide): a skeletal model, three merged locomotion clips, a capsule collider, and an enabled Player Controller. This guide adds the jump on top.

Extra animation clips you need

Export these as separate FBX files sharing the character's skeleton (Mixamo works well):

  • Jump — the launch / rising pose (a "jump up" clip). One clip is enough to start.
  • Fall — the airborne descending / falling-idle loop.
  • Land — the touchdown / landing recovery (a short one-shot).

Minimal build: even a single Jump clip covering the whole airborne phase works — add Fall and Land later for polish.

Tip — set the jump height first In the Character Editor's Movement tab, set Jump Speed (e.g. 5) so the character actually leaves the ground. This is the upward launch velocity; higher = higher jump. Gravity and landing are handled by the character controller.

Step 1 — add the air clips as animation sources

Open Character Editor, go to the Mesh tab (or the Animation tab's Animation Sources section) and add the new files alongside your Idle/Walk/Run, naming their clips clearly:

FileClip NameStrip Root Motion
Jump.fbxJumpYes (keep it in place)
Fall.fbxFallYes
Land.fbxLandYes

They merge onto the model by bone name, joining the clip list next to Idle/Walk/Run.

Step 2 — build the ground locomotion

On the Animation tab, with Idle/Walk/Run present, click Create 1D Locomotion. This makes the grounded Locomotion state (a blend space on Speed). This is your "on the ground" state; the jump states sit beside it.

Step 3 — add the air states

In the States section, add three states, each pointing at the matching clip:

StateClipLoopNotes
JumpJumpNoThe rising phase. Plays once as the character leaves the ground.
FallFallYesLoops while descending (air time can vary).
LandLandNoOne-shot on touchdown, then back to Locomotion.

Step 4 — declare the parameters

In the Parameters section add these (the engine drives them each frame in Play — you just declare them so transitions can read them):

ParameterTypeMeaning
IsGroundedBooltrue while standing on the ground
IsFallingBooltrue while airborne and moving downward
VerticalSpeedFloatvertical velocity: positive rising, negative falling
Names must match exactly Spell the parameters IsGrounded, IsFalling, VerticalSpeed (case-sensitive). The controller writes to those exact names; a typo means the transition never fires and the character "sticks" to the ground pose in the air.

Step 5 — wire the transitions

In the Transitions section, connect the states like this:

Locomotion→Jump →Fall →Land →Locomotion
From → ToConditionFade
Locomotion → JumpIsGrounded is false0.10
Jump → FallVerticalSpeed < 0  (or IsFalling is true)0.15
Fall → LandIsGrounded is true0.10
Land → LocomotionExit Time = 1.0 (when the Land clip finishes)0.15

Two robustness edges make it forgiving:

From → ToConditionWhy
Jump → LandIsGrounded is trueVery short hops that never reach the Fall phase.
Locomotion → FallIsGrounded is false & VerticalSpeed < 0Walking off a ledge (falling without a jump).
Tip — Can Interrupt Tick Interrupt Blend (canInterrupt) on the air transitions so a jump can trigger even mid-blend. Leave Land → Locomotion on Exit Time so the landing plays fully before movement resumes.
Minimal version Just want "off the ground = jump pose"? Use one Jump state and two transitions: Locomotion → Jump when IsGrounded is false, and Jump → Locomotion when IsGrounded is true. Add Fall/Land later.

How the parameters are driven (for reference)

You don't set these yourself — in Play the engine updates them every frame from the character controller. This is what each reflects:

ParameterDriven from
IsGroundedthe capsule's ground contact (true on the floor)
IsFallingairborne and vertical velocity < 0
VerticalSpeedthe body's Y velocity (jump gives a positive spike, then gravity pulls it negative)
Speedhorizontal move speed — still drives the grounded Locomotion blend

Step 6 — save, place, and play

  1. Save the .3dgcharacter asset (Character Editor menu → Save).
  2. Add it to the scene (drag from Assets, or Add to Scene) onto ground that has a collider, and confirm Jump Speed is set in Movement.
  3. Enter Play. W A S D move, Shift run, Space jump, Mouse look.
  4. Verify the cycle: pressing Space plays Jump as the character rises, blends to Fall as it descends, then Land on touchdown, and returns to Idle/Walk/Run.
Editor vs Play In the editor viewport characters hold a paused idle by default, so you won't see the jump graph run until you enter Play (or toggle View → Animate Characters in Editor). The jump only plays in Play mode, where the physics drives the parameters.

Troubleshooting

SymptomCause & fix
Character doesn't leave the groundJump Speed is 0 in the Movement tab, or there's a ceiling. Set Jump Speed (e.g. 5).
Jumps physically but the pose never changesTransition conditions don't match. Check the parameter names (IsGrounded/IsFalling/VerticalSpeed) and that Locomotion → Jump uses IsGrounded == false.
Stuck in the Jump pose after landingMissing the return edge. Add Fall → Land (or Jump → Locomotion) on IsGrounded == true, and Land → Locomotion on Exit Time.
Fall never plays (jumps straight to Land)Air time is short or the Fall edge is wrong. Use VerticalSpeed < 0 for Jump → Fall; raise Jump Speed to lengthen air time.
Feet slide during the jumpRoot motion in the air clips. Tick Strip Root Motion on Jump/Fall/Land.
Landing pose snaps in hardIncrease the transition Fade (e.g. 0.15) into Land and back to Locomotion.
T-pose in the airThe air clip didn't merge (name mismatch). Confirm the state's Clip matches a source's Clip Name.
Going further Split Jump into JumpStart → JumpLoop → JumpApex for a weightier feel, add a double-jump by watching VerticalSpeed spikes, or use Speed in the Land transition to pick a running vs standing landing. The same parameter-driven pattern extends to all of it.
