1. ECS — entities, components, systems

Every object is an entity (an id) carrying components (plain data) in an engine::ecs::Registry. Behaviour is applied by systems (functions that iterate components) and by scripts.

Key components

ComponentFields
ecs::Transformglm::vec3 position, glm::vec3 scale, glm::quat rotation; mat4 Model().
ecs::RuntimeNamestd::string value — the object's name; how scripts & saves find it across a reload.
ecs::LinearVelocityglm::vec3 velocity.
ecs::AngularVelocityglm::vec3 axis, float radiansPerSecond.
Healthfloat hp,maxHp, bool alive; Damage(d), Reset(full).
ecs::Collider, ecs::RigidBody, ecs::LightSee §7 / §4.
ecs::MeshPBR, ecs::ModelAsset, ecs::SkinnedModelAsset, AnimatedModelDrawables & assets — §4/§6.

Reading & writing components

Code 
// Iterate all entities that have BOTH a Transform and Health:
registry.view<ecs::Transform, Health>().each(
    [&](ecs::Entity e, ecs::Transform& t, Health& h) {
        if (!h.alive) t.position.y -= 2.0f * dt;   // sink corpses
    });

// Single-component view:
registry.view<ecs::Light>().each([](ecs::Entity, ecs::Light& L){ L.intensity *= 0.5f; });

From inside a script

A script already knows its own entity, so component access is one call:

Code 
class Elevator final : public engine::Script {
public:
    void OnFixedUpdate(float dt) override {
        // read / write my own components
        if (auto* t = Transform())
            t->position.y += m_dir * 1.5f * dt;

        // reach another named object
        if (auto* doorT = FindTransform("Door"))
            doorT->position.x = t->position.y;         // silly linkage, but shows lookup

        // component test + add on the fly
        if (!Has<Health>()) Add<Health>(Health{ 50.f, 50.f, true });
        if (Health* h = TryGet<Health>(); h && h->hp <= 0) DestroySelf();
    }
private:
    float m_dir = 1.0f;
};
Entity ids are not stable across a scene reload or save/load. To refer to a specific object later, use its RuntimeName via FindObject(name). Give every object you script against a clear name in the Hierarchy.

2. Scenes, prefabs, worlds & level streaming

You edit an editor scene; the editor exports a runtime scene that Play mode and the standalone player consume. Reuse objects with prefabs; split big games into streamable levels inside a world.

Prefabs

Editor 
1. Build an object (mesh + material + collider + scripts).
2. Right-click it → Create Prefab → save Coin.3dgprefab.
3. Drag Coin.3dgprefab into the scene to stamp instances.
4. Edit the prefab asset; placed instances update to match.

Spawning at runtime

Code 
// Spawn a copy of an existing scene object (a prototype) at a position:
void FireProjectile(const glm::vec3& muzzle) {
    ecs::Entity shot = SpawnFromObject("BulletPrototype", muzzle);
    if (auto* v = Registry()->TryGet<ecs::LinearVelocity>(shot))
        v->velocity = Forward() * 30.0f;
}
// A bare entity:
ecs::Entity marker = SpawnEmpty("Marker", hitPoint);

Scene transitions & level streaming

Scripts request flow changes; the host performs them after the current update.

Code 
void OnFixedUpdate(float) override {
    if (WasTriggerEntered(FindObject("ExitDoor")))
        RequestSceneLoad("Level2");             // full scene switch (editor Play + player)

    if (WasTriggerEntered(FindObject("BridgeTrigger"))) {
        RequestLevelLoad("Chunk_East");         // stream a level in  (packaged worlds)
        RequestLevelUnload("Chunk_West");       // and drop the old one
    }
}
Editor parity RequestSceneLoad works in editor Play now, so you can test level flow without packaging. Level streaming runs in packaged worlds (the editor Play preview is a single in-memory scene).

3. Assets — import, registry, references, cooking

Source art becomes an engine-owned native asset with a stable id. Scenes reference the id (paths are a fallback); the runtime resolves ids to GPU/runtime objects; the cooker copies only what a scene reaches.

Importing (drag-and-drop)

Editor 
1. Drag files from Explorer onto the editor window.
2. The Import Settings dialog lists each file with its detected type:
     - Models are peeked for a skeleton →
         has skeleton + mesh  → Skeletal Mesh   (default)
         skeleton, no mesh    → Animation Only
         no skeleton          → Static Mesh
       Row shows e.g. "[Model] hero.fbx (skeleton, 1 mesh, 6 anim)". Override per file.
     - Textures get sRGB + Smooth toggles. sRGB defaults OFF for names containing
       normal / rough / metal / _orm / mask / height / ao (linear data maps).
3. Set the Target Folder (defaults to the current Content folder) → Import.
4. Console logs each result; the browser + asset registry refresh.

Native vs authored assets

Native (engine-owned binary)Authored (editable document)
.3dgmesh static mesh, .3dgskmesh skinned mesh, .3dgskel skeleton, .3dganim animation, .3dgtex texture .3dgmat material, .3dgshader shader graph, .3dgclip/.3dggraph/.3dgcharacter animation, .particle, .hud, .3dgprefab, .btgraph

Referencing an asset on an object

Editor 
Select the object → Inspector → assign the Model / Material / Character asset,
or drag the asset from the Content Browser onto the object.
Cooking Packaging exports the runtime scene and runs the AssetCooker, which walks the dependency graph from the scene and copies only reachable assets (content-hashed, topologically ordered). Unused assets never ship.

4. Rendering, lighting & cameras

Physically-based rendering with automatic frustum culling, LODs, shadows, and instancing. You place drawables + lights; the frame loop renders them. A separate skinned path handles characters.

Making an object visible

Editor 
1. Drag a mesh into the viewport (or add a primitive).
2. Assign a .3dgmat material in the Inspector.
3. Add a directional Light as the "sun"; set the environment (sky / IBL) for ambient.
4. Static geometry: give it a Static Collider so physics & AI see it (§7).

Lights

Light typeUse
DirectionalThe sun; casts cascaded shadows across the whole scene.
PointLocal omni light (lamps, torches); omnidirectional shadows.
SpotCone light (flashlights); perspective shadows.
Code 
// Flicker a torch's point light from a script:
void OnUpdate(float dt) override {
    m_t += dt;
    if (auto* L = TryGet<ecs::Light>())
        L->intensity = 3.0f + 0.4f * std::sin(m_t * 22.0f);
}

Cameras

In Play the camera follows the PlayerController view mode (Third Person / First Person / Isometric / Platformer), or a Camera Zone trigger blends to an authored preset. Scripts add feel and cutscenes:

Code 
if (justLanded)          Camera().Shake(0.6f, 0.3f, 20.0f);      // intensity, duration, freq
if (bossDefeated) {
    Camera().PlaySequence("VictoryCam", /*lockInput*/true, /*skippable*/true);
    if (WasCameraSequenceFinished("VictoryCam")) RequestSceneLoad("Credits");
}
Two-sided preview The Material Maker preview disables backface culling so you can inspect interiors; scene rendering culls backfaces of closed solids for speed (glass and flat planes stay two-sided).

5. Materials, textures & shader graphs

Author materials in the Material Maker with a live PBR preview; build custom materials as shader graphs. The same compiler powers preview and scene, so what you see is what ships.

Authoring a material

Editor 
1. Panels → Material Maker → New.
2. Set Albedo (+ albedo map), Metallic/Roughness (+ packed map), Normal (+ map, strength).
3. Optional lobes: Clearcoat (car paint), Transmission/IOR (glass), Sheen (cloth),
   Subsurface (skin), Anisotropy (brushed metal). Set Emissive for glow.
4. Set UV scale/offset/rotation. Save Rock.3dgmat.
5. Assign it to objects (Inspector or drag).

Material fields (PbrMaterial)

FieldMeaning
albedo, albedoMapBase colour (sRGB texture).
metallic, roughness, metalRoughMapSurface response (often one packed texture).
normalMap, normalStrengthSurface detail (linear texture).
emissiveAdditive glow — flash it on an event.
opacity, blendMode, alphaCutoffTransparency / cutout.
clearcoat, transmission, ior, sheenColor, subsurface, anisotropyAdvanced BRDF lobes.

Reacting from a script (tint / emissive flash)

Code 
// AnimatedModel exposes runtime material overrides (tint / emissive glow):
void FlashHit() {
    if (auto* am = TryGet<engine::AnimatedModel>()) {
        am->emissive = glm::vec3(1.5f, 0.2f, 0.2f);          // red glow now
        Delay(0.12f, [am]{ am->emissive = glm::vec3(0.0f); }); // clear shortly after
    }
}
Colour space Import colour maps as sRGB and data maps (normal / roughness / metal / AO) as linear. The drag-drop Import dialog pre-selects this from the filename — verify it, since a normal map decoded as sRGB shades wrong.

6. Skeletal animation — clips, graphs, characters

Three authored assets stack into one runtime controller: a clip is one take; a graph is a state machine of clips; a character binds a graph to a rig + collider + controller. Scripts drive parameters and fire one-shot actions.

1) Clip Editor — .3dgclip

Editor 
1. Clip Editor → pick a source FBX / .3dganim.
2. Pick the take in the "Clip" dropdown (blank = first take).
3. Set Strip Root Motion / Loop / Speed. "Action Clip" = one-shot (script-triggered).
4. Name it (Idle / Walk / Run) and Save Idle.3dgclip.

2) Graph Editor — .3dggraph

Editor 
1. Graph Editor → Add Clip… → add your Idle/Walk/Run .3dgclip assets.
2. Add a Float parameter "Speed".
3. Create 1D Locomotion → a blend space state (Idle@0, Walk@1.5, Run@4) on Speed.
4. Watch the Validation strip at the top: fix red (unresolved clips / bad transitions)
   and yellow (always-true transitions, undeclared params, dead ends) before testing.
5. Save Locomotion.3dggraph.
Transition footgun A Float transition of Speed >= 0 is always true and skips the state on frame 1. Use Speed > 0.1; use == for Bool/Trigger. New transitions now default to a safe threshold, and the Validation strip flags the rest.

3) Character Editor — .3dgcharacter

Editor 
1. Character Editor → set the skeletal model + material.
2. Animation Graph → reference Locomotion.3dggraph. The preview now plays its Idle;
   drag the Speed slider to preview idle→walk→run without entering Play.
3. Set the capsule Collider; enable Player Controller (Third Person) if it's the hero.
4. (Optional) Foot IK → Enable; auto-detects leg bones; tune Trace Up/Down, Foot Height,
   Pelvis Adjust, IK Weight. Grounds feet on slopes/steps at runtime.
5. Save Hero.3dgcharacter and place it in the scene (name it "Player").

Runtime parameters & driving them

In Play the controller is driven each frame with Speed, Direction, IsMoving, IsStopping, IsGrounded, IsFalling, VerticalSpeed, TurnRate… A player controller feeds these automatically; a script can override or add its own:

Code 
void OnUpdate(float) override {
    Anim().SetParameter("Speed", glm::length(PlanarVelocity()));
    Anim().SetBool("IsGrounded", grounded);

    if (Input().KeyPressed(GLFW_KEY_SPACE)) Anim().SetTrigger("Jump");
    if (Input().KeyPressed(GLFW_KEY_F))     Anim().PlayAction("Attack"); // one-shot montage

    // gate movement while a full-body action plays:
    if (Anim().IsActionPlaying() && Anim().IsMovementLocked()) return;
}

Root motion & animation events

Set a state's Root Motion flag to move (and turn) the character from the clip itself — ideal for turn-in-place and curved locomotion. Author notify events on clips (e.g. a "hit" frame) and react to them:

Code 
void OnUpdate(float) override {
    if (WasAnimationEvent("hit"))     ApplyMeleeDamage();
    if (WasAnimationEvent("footstep")) Audio().PlayCue("Content/SFX/step.wav");
}
Actions vs states Locomotion is a graph state driven by parameters. An Action Clip (authored in the Clip Editor, called by name with PlayActionClip("Roll") or PlayAction("Attack")) plays over locomotion on a bone mask — use it for attacks, casts, and reactions.

7. Physics — colliders, bodies, queries, joints, ragdolls

An impulse solver with a spatial-hash broadphase. Give entities colliders (and optionally rigid bodies); the fixed step integrates and resolves them. Run gameplay that touches collision in OnFixedUpdate.

Components & fields

ComponentKey fields
ecs::Collidershape (Sphere/Box/Capsule/Cylinder/Cone/Pyramid/Torus/Staircase/Plane), halfExtents/radius/halfHeight, restitution, friction, isTrigger, layer, mask.
ecs::RigidBodyinvMass (0 = static), velocity, useGravity, allowSleep, ccd, freezeRotation, kinematic.
Editor 
Inspector → + Add Component → Collider / Rigid Body, or use Physics Setup presets:
  Dynamic Body    = rigid body + fitted collider (falls, collides)
  Static Collider = collider only, immovable (floors, walls)
  Trigger         = overlap-only collider (checkpoints, pickups, zones)
"Match Collider to Scale" refits the collider after you resize the object.

Movement (kinematic controller)

Code 
void OnFixedUpdate(float dt) override {
    glm::vec3 move(0);
    if (Input().KeyDown(GLFW_KEY_W)) move.z -= 1;
    if (Input().KeyDown(GLFW_KEY_S)) move.z += 1;
    if (Input().KeyDown(GLFW_KEY_A)) move.x -= 1;
    if (Input().KeyDown(GLFW_KEY_D)) move.x += 1;
    if (auto* rb = TryGet<ecs::RigidBody>())        // kinematic body: set velocity
        rb->velocity = glm::length(move) > 0 ? glm::normalize(move) * 6.0f : glm::vec3(0);
}

Raycast & sphere-cast queries

Code 
// Ground check under the feet (systems receive the PhysicsWorld; scripts can be handed one):
engine::Ray down{ Transform()->position + glm::vec3(0,0.1f,0), glm::vec3(0,-1,0) };
engine::RaycastHit hit = physics.Raycast(*Registry(), down,
                             /*maxDist*/0.4f, /*layerMask*/0xFFFFFFFF, /*ignore*/Self());
bool grounded = hit.hit;
glm::vec3 groundNormal = hit.normal;

// Shotgun a target and read what we struck:
engine::Ray aim{ muzzle, forward };
engine::RaycastHit shot = physics.Raycast(*Registry(), aim, 100.f, 0xFFFFFFFF, Self());
if (shot.hit)
    if (auto* hp = Registry()->TryGet<Health>(shot.entity)) hp->Damage(25.f);

physics.SphereCast(reg, start, end, radius, ignore) sweeps a volume — use it for camera booms and thick probes that a thin ray would slip through.

Triggers & contact events

Code 
void OnFixedUpdate(float) override {
    ecs::Entity player = FindObject("Player");
    if (WasTriggerEntered(player)) { OpenDoor();  Audio().PlayCue("door_open.wav"); }
    if (WasTriggerExited(player))  { CloseDoor(); }
    if (IsTriggerTouching(player))  m_dwellTime += FixedDt();  // still inside
}

Joints & ragdolls

Connect bodies with Distance / Rope / Spring joints in the Inspector's Physics Joints section (pendulums, ropes, springs). A character with a Ragdoll (enabled on Health, activate-on-death) swaps animation for connected physics bodies at zero HP:

Editor 
Inspector → Health → Ragdoll On Death → tune Mass, Physics Bodies, Body Thickness,
Linear/Angular Damping, Death Impulse. At 0 HP the mesh collapses under physics.

8. Gameplay & the scripting API

Gameplay logic is C++ scripts deriving engine::Script, attached to objects. The editor generates registration; after a script build they run in Play and in packaged builds. Each project's scripts are isolated.

Creating & attaching a script

Editor 
1. Select an object → Inspector → + Add Script → name it (e.g. Coin) → Create + Attach.
   Files land in Content/Scripts/Coin.h and are registered for THIS project only.
2. Edit Coin.h (built-in editor or your IDE).
3. Compile Scripts (Script Editor / prompt). Enter Play — the script runs.

Lifecycle

OnCreate()Once on spawn / entering Play — read fields, cache lookups.
OnUpdate(dt)Per rendered frame (variable dt) — input, camera, cosmetics.
OnFixedUpdate(dt)Per physics step (fixed dt) — movement, forces, collision-facing logic.
OnDestroy()Before removal — release, notify.

Designer-tunable fields

Expose values so designers tune a script in the Inspector without recompiling:

Code 
void OnCreate() override {
    m_speed    = GetFieldFloat("moveSpeed", 6.0f);
    m_maxJumps = GetFieldInt("maxJumps", 2);
    m_target   = GetFieldEntity("focus");            // an object picker in the Inspector
    m_hitSfx   = GetFieldAsset("hitSound");          // an asset picker
}

Timers & sequences

Code 
// repeating spawner
int id = SetTimer(2.0f, [this]{ SpawnFromObject("Enemy", SpawnPoint()); }, /*repeat*/true);
// one-shot delay
Delay(0.5f, [this]{ Camera().Shake(0.4f); });
// a scripted sequence across frames
Sequence().Do([this]{ OpenGate(); })
          .Wait(3.0f)
          .WaitUntil([this]{ return AllEnemiesDead(); })
          .Do([this]{ Game()->Win(); });

A full gameplay script

Code 
#include <engine/gameplay/Script.h>

class Coin final : public engine::Script {
public:
    void OnCreate() override { m_spin = GetFieldFloat("spinSpeed", 120.0f); }

    void OnUpdate(float dt) override {
        if (auto* t = Transform())
            t->rotation = glm::rotate(t->rotation, glm::radians(m_spin*dt), glm::vec3(0,1,0));
    }
    void OnFixedUpdate(float) override {
        if (WasTriggerEntered(FindObject("Player"))) {
            Game()->AddScore(1);
            Audio().PlayCue("Content/SFX/coin.wav");
            Particles().Burst(24);
            SaveInt("coins", GetSavedInt("coins") + 1);   // persists across saves
            DestroySelf();
        }
    }
private:
    float m_spin = 120.0f;
};
GameMode Game() is the shared score/state object: AddScore/Score, Win()/Lose(), State(), Message(). HUD widgets bind to these by name (§12).

9. AI & navigation

Agents = a Nav Agent component + a navmesh/grid + a brain (built-in state machine or a Behavior Graph) + perception (vision cone with line-of-sight, and a decaying hearing field).

Authoring an agent

Editor 
1. Bake nav: open the Navigation preview → set bounds → Build (navmesh over the floor).
2. Place a character; Inspector → + Add Component → Nav Agent:
     Speed / Max Force / Reach Radius / Repath Interval,
     Vision Range + Half-Angle, Hearing Range, Team,
     Chase Target (a named object) OR Auto-target (nearest enemy, different non-zero team).
3. Give it Health. Optionally assign a Behavior Graph (.btgraph); otherwise the built-in
   Patrol → Chase → Search brain runs (reacts to sightings & noises; squads share alerts
   and flank a shared target).

How perception drives behaviour

Each frame the host resolves the agent's target, tests vision (in-cone + a line-of-sight raycast that ignores the agent itself), and ages the sound field (fast movement emits footstep noise; HP loss emits loud combat noise). Seeing beats hearing; a heard noise becomes a search point of interest.

Custom behaviour from a Behavior Graph

Editor 
Behavior Graph panel → compose Tasks (move-to, attack), Decorators (conditions),
Services (periodic checks) over a Blackboard. Create custom nodes from the templates
(Task / Decorator / Service) → they generate .h files registered for this project.

Reacting to AI from a gameplay script

Code 
// A guard script that shouts and speeds up when it first sees the player.
void OnUpdate(float) override {
    const bool sees = /* read the agent's perceivesTarget via a shared component/flag */;
    if (sees && !m_wasAlerted) {
        Audio().PlayCue("Content/SFX/alert.wav");
        Anim().SetTrigger("Alert");
    }
    m_wasAlerted = sees;
}
Scale Auto-targeting snapshots candidate targets once per frame (cheap even with many agents). For hundreds of agents, back the nearest-enemy search with the physics spatial hash.

10. Audio

The mixer plays up to 64 voices with priority-based voice stealing and per-bus groups (SFX / Music / Dialogue). Attach spatial sources to objects, or fire cues from scripts.

A spatial sound source

Editor 
Inspector → + Add Component → Audio Source:
  clip, volume, pitch, looping, autoplay, bus (SFX/Music/…),
  attenuation (min/max distance, rolloff), Doppler, cone, occlusion, priority.
Code 
// Control the object's own source:
void OnCreate() override { Audio().SetLooping(true); Audio().Play(); }
void OnUpdate(float) override {
    Audio().SetVolume(engineLoad);          // e.g. an engine hum tracking throttle
    Audio().SetPitch(0.8f + engineLoad*0.6f);
}
void OnDestroy() override { Audio().Stop(); }

One-shot cues

Code 
Audio().PlayCue("Content/SFX/coin.wav");            // 2D
Audio().PlayCue("Content/SFX/impact.wav", /*spatial*/true);  // positioned at this entity

Adaptive music & mix

Code 
void OnCreate() override { Audio().LoadMusic("Content/Music/level.adaptive"); }
void OnUpdate(float) override {
    Audio().SetMusicState(inCombat ? "combat" : "explore");  // beat-synchronised switch
    if (dialogueLine) Audio().SetDialogueDucking(true);      // duck music under VO
}
Buses & snapshots Route sources to buses and apply mixer snapshots (Audio().ApplySnapshot(preset, transitionSeconds)) for scene-wide mood changes (e.g. an underwater or paused mix).

11. Particles

Author systems in the Particle Editor (emission, shape, velocity, color/size over life, forces), attach them to objects, and drive them from scripts.

Authoring

Editor 
Particle Editor → start from a preset (Fire / Smoke / Sparks / Magic) → tune modules:
  Emission rate + bursts, Shape (cone/sphere/box), Velocity, Color/Size over Life, Forces
  (gravity, drag, turbulence). Save Impact.particle and add it to an object.

Driving from a script

Code 
// A muzzle flash that bursts on fire and a thruster that scales with throttle.
void Fire() {
    Particles().Burst(30);                 // one-shot burst on THIS entity's system
    Particles().Play(FindObject("Smoke")); // start another object's system
}
void OnUpdate(float) override {
    Particles().SetRate(throttle * 200.0f);   // continuous emission tracks input
    Particles().SetSpeed(bulletTime ? 0.2f : 1.0f);  // slow the sim in bullet-time
    if (dead) Particles().Stop(/*clear*/true);
}
Events Combine with animation notifies — WasAnimationEvent("cast") → Particles().Burst(...) — so effects fire exactly on the keyframe.

12. UI & HUD

A HUD (.hud) is a document of widgets that bind to runtime values by name and draw each frame. Author it in the HUD editor; the runtime draws the scene's HUD plus the save menu and status overlay.

Authoring & binding

Editor 
HUD editor → add widgets:
  - Health bar / text  → binds to the player's Health (health / maxhp / healthFraction).
  - Text "Score: {}"   → binds NamedString/NamedFloat "score" from GameMode.
  - Message            → binds "gamemessage" / "gamestate" for end screens.
  - Button             → action (Restart / Exit) for pause & end screens.
Save Game.hud and reference it from the scene.

Pushing values from a script

GameMode values (score, time, gamestate, gamemessage) and the player's Health flow to the HUD automatically. Set them via gameplay:

Code 
Game()->AddScore(100);            // HUD "score" updates
Game()->SetMessage("Wave 3");     // HUD "gamemessage" shows it
if (bossDead) Game()->Win();      // HUD end screen (VICTORY) appears
Runtime menus The standalone player overlays an in-game save/load menu (§13) on top of the HUD, plus a status line and controls hint.

13. Save / Load

The SaveGame module snapshots world state into numbered slots with metadata and restores it after a scene reload, matching entities by RuntimeName. Scripts also get a typed key/value store and checkpoints.

What is captured

Captured per named entityPlus
Transform (position/rotation/scale), Health (hp/maxHp/alive), Linear & Angular velocity The flat key/value store scripts write; slot metadata (display name, source scene, timestamp).

Typed values & checkpoints

Code 
SaveInt("coins", 12);      SaveFloat("bestTime", 41.7f);
SaveBool("doorOpen", true); SaveVec3("lastPos", Transform()->position);
int coins = GetSavedInt("coins", 0);                 // 0 if unset

if (WasTriggerEntered(FindObject("Checkpoint")))
    SaveCheckpoint("cp1", Transform()->position);
glm::vec3 respawn;
if (LoadCheckpoint("cp1", &respawn)) Transform()->position = respawn;

Full save slots

Code 
void OnFixedUpdate(float) override {
    if (WasTriggerEntered(FindObject("SaveAltar")))
        SaveGameToSlot(1, "Cathedral");     // captures the whole world → slot 1
    if (playerDied)
        LoadGameFromSlot(1);                // reloads the saved scene + restores state
}

In-game menu (packaged player)

Editor 
In the standalone player at runtime:
  F5        quick-save to slot 0 (shows a "Saved" toast)
  F9        open/close the Load menu (pauses the game)
  Up/Down   select a slot     Enter  load     Del  erase     Esc  close

A load reloads the saved scene, then re-applies the snapshot — the same path LoadGameFromSlot uses, so menu and script loads behave identically.

Extending To persist more (inventory, custom per-entity state), add fields to the capture in engine/gameplay/SaveGame.h (CaptureSaveGame / ApplySaveGame).
