A hands-on 3DGEngine tutorial

Cloud Climber

Build a 3D platformer — and learn the engine while you do it.

Nine lessons: a side-on 2.5D level with the Platformer camera, a jumping hero, moving and crumbling platforms, coins, hazards with respawn checkpoints, a HUD, sound and particle juice, and a goal flag with win/lose and a packaged build. Every lesson names the engine system it teaches. Print to PDF with Ctrl+P → Save as PDF (A4).

What you'll build

A run-and-jump course: side-on camera, run left/right and jump across gaps and moving platforms, grab coins, dodge spikes, respawn at checkpoints when you fall, and reach the goal flag — then ship it as a standalone.

Lessons

  1. Set up the project & import — projects, importing
  2. The level & the platformer camera — scenes, Platformer controller, jump
  3. Moving & crumbling platforms — Mover component, scripts, timers
  4. Coins & score — triggers, prefabs, GameMode
  5. Hazards, falling & respawn — damage triggers, checkpoints
  6. The HUD — UI binding
  7. Feel: jump juice — camera shake, hit-stop, SFX on landing
  8. Polish: audio & particles — cues, dust, sparkles
  9. The goal, win & ship — GameMode, packaging
Assets Build it entirely from primitives if you like: a capsule hero, cubes for platforms, a small sphere for coins, thin cubes for spikes, a cylinder for the goal. A rigged character with idle/run/jump takes makes it sing, but is optional — the Platformer controller works with a plain capsule too.
1

Set up the project & import

You'll learn Projects (with isolated scripts) and importing — or building from primitives.
  1. File → New Project, name it CloudClimber.
  2. Optional: drag a rigged hero FBX (idle/run/jump takes) and any props onto the window; the Import dialog handles types. Otherwise use primitives — a capsule hero works with the Platformer controller.
  3. Drop a few WAVs into Content/SFX/ (jump.wav, coin.wav, land.wav, hurt.wav).
Checkpoint A fresh CloudClimber project is open.
2

The level & the platformer camera

You'll learn The Platformer Player Controller — a side-on 2.5D camera with run-and-jump movement locked to one axis.
  1. Ground & platforms — add a long thin Cube as the starting ground and several more Cubes as platforms at rising heights and across gaps. Give each a Static Collider (Physics Setup → Static Collider) so you can stand on them.
  2. Player — add a Capsule, name it Player, give it a Capsule Collider and a Player Controller. Set Camera Mode = Platformer.
  3. Set the Camera Yaw to pick the run axis: 0 = run along Z, -90 = run along X. Set the Side Distance for how far back the camera sits. Set a Jump Speed that clears your platform gaps.
  4. Add a PlayerStart and press Play. The camera is side-on; move left/right along the run axis, and Space jumps. The character turns to face its travel direction automatically.
Checkpoint A side-scrolling view where you run and jump between platforms. Tune Jump Speed and platform spacing until the jumps feel fair.
The run axis Platformer mode confines movement to one horizontal line (chosen by Camera Yaw) so it plays like a 2.5D side-scroller while everything stays 3D. Yaw -90 runs along X (classic left-to-right); 0 runs along Z.
3

Moving & crumbling platforms

You'll learn The authored Mover component for platforms that oscillate, and a script for platforms that crumble when you stand on them.

3a. A moving platform (no code)

  1. Add a Cube platform with a Static Collider.
  2. Inspector → + Add Component → Mover. Set Axis (e.g. (1,0,0) for horizontal, (0,1,0) for an elevator), a Distance, a Speed, and a Phase to offset it. It now glides back and forth on its own.
  3. Play and ride it across a gap.
Riding platforms Stand on a Mover platform and it carries you. If your character slides off a fast one, lower its Speed or widen the platform — moving-platform "stick" depends on the contact each fixed step.

3b. A crumbling platform (script)

  1. Add a Cube platform (Static Collider), name it Crumble, and attach a Crumble script:
#include <engine/gameplay/Script.h>
#include <cmath>

class Crumble final : public engine::Script {
public:
    void OnFixedUpdate(float) override {
        if (m_triggered) return;
        auto* me = Transform();
        auto* p  = FindTransform("Player");
        if (me && p) {
            const glm::vec3 d = p->position - me->position;   // is the player on top?
            if (std::abs(d.x) < 1.3f && std::abs(d.z) < 1.3f && d.y > 0.0f && d.y < 1.7f) {
                m_triggered = true;
                Delay(0.5f, [this]{ Particles().Burst(20); DestroySelf(); });  // drop out
            }
        }
    }
private:
    bool m_triggered = false;
};
Checkpoint One platform glides on a Mover; another vanishes half a second after you land on it — forcing you to keep moving. (We add the puff of dust in Lesson 8.)
4

Coins & score

You'll learn Trigger pickups, GameMode score, and reusing objects with prefabs — the platformer's collectibles.
  1. Add a small Sphere, name it Coin, give it a Trigger collider and a bright emissive material.
  2. Attach a Coin script:
#include <engine/gameplay/Script.h>

class Coin final : public engine::Script {
public:
    void OnUpdate(float dt) override {                       // bob + spin
        m_t += dt;
        if (auto* t = Transform()) {
            t->position.y += std::sin(m_t * 3.0f) * dt * 0.3f;
            t->rotation = glm::rotate(t->rotation, glm::radians(120.0f*dt), glm::vec3(0,1,0));
        }
    }
    void OnFixedUpdate(float) override {
        if (WasTriggerEntered(FindObject("Player"))) {
            Game()->AddScore(1);
            Audio().PlayCue("Content/SFX/coin.wav");
            Particles().Burst(16);
            DestroySelf();
        }
    }
private:
    float m_t = 0.0f;
};
  1. Make it a prefab (Coin.3dgprefab) and line coins along your jump arcs and over gaps to reward risky routes.
Checkpoint Coins bob and spin, vanish on touch, and the score rises. You've reused a prefab and read Game().
5

Hazards, falling & respawn

You'll learn Damage triggers, a kill-plane for falls, checkpoints via the shared key/value store, and respawning the player.

5a. Player lives & respawn

  1. Give Player a Health component with hp = 3 (three lives).
  2. Attach a PlayerLife script that respawns on a fall and ends the game at zero lives. Checkpoints (next) store the respawn point in the shared store:
#include <engine/gameplay/Script.h>

class PlayerLife final : public engine::Script {
public:
    void OnCreate() override {
        m_start = Transform() ? Transform()->position : glm::vec3(0);
        SaveVec3("respawn", m_start);                       // initial checkpoint = start
    }
    void OnFixedUpdate(float) override {
        auto* t = Transform(); if (!t) return;
        if (t->position.y < m_killY) LoseLifeAndRespawn();   // fell off the world

        if (auto* h = TryGet<Health>(); h && !h->alive) {
            Game()->SetMessage("Out of lives!");
            Game()->Lose();
        }
    }
    void LoseLifeAndRespawn() {
        if (auto* h = TryGet<Health>()) h->Damage(1.0f);      // -1 life
        Audio().PlayCue("Content/SFX/hurt.wav");
        if (auto* t = Transform()) t->position = GetSavedVec3("respawn", m_start);
        if (auto* rb = TryGet<engine::ecs::RigidBody>()) rb->velocity = glm::vec3(0);
    }
private:
    glm::vec3 m_start{0};
    float m_killY = -10.0f;
};

5b. Spikes & checkpoints

  1. Spike — a thin Cube with a Trigger collider and a Spike script that hurts and respawns the player:
void OnFixedUpdate(float) override {
    if (WasTriggerEntered(FindObject("Player"))) {
        if (auto* pt = FindTransform("Player"))
            pt->position = GetSavedVec3("respawn", pt->position);
        if (auto* h = TryGet<Health>(FindObject("Player"))) h->Damage(1.0f);
        Audio().PlayCue("Content/SFX/hurt.wav");
    }
}
  1. Checkpoint — a Trigger volume with a Checkpoint script that records the respawn point everyone reads:
void OnFixedUpdate(float) override {
    if (WasTriggerEntered(FindObject("Player"))) {
        if (auto* t = Transform()) SaveVec3("respawn", t->position + glm::vec3(0,1,0));
        Game()->SetMessage("Checkpoint!");
    }
}
Checkpoint Falling off or touching spikes costs a life and warps you to the last checkpoint; three deaths ends the run. Checkpoints and death share one value — "respawn" in the key/value store — so no script has to call another.
6

The HUD

You'll learn Binding UI to runtime values — coins and lives that update themselves.
  1. HUD editor → add a text Coins: {} bound to score.
  2. Add a lives display bound to the player's Health (the health bar, or a text bound to hp). With hp = 3, this reads as three lives.
  3. Add a centered message bound to gamemessage — shows "Checkpoint!", "Out of lives!", and your win text.
  4. Save Game.hud and reference it from the scene.
Checkpoint Coins and lives update live as you play, and banners appear at checkpoints and on death — no glue code.
7

Feel: jump juice

You'll learn Small feedback that makes jumping feel great — a landing thud, camera shake, and a jump cue — using the camera and audio APIs.
  1. Attach a JumpJuice script to the Player. It infers landings from vertical speed (no controller internals needed):
#include <engine/gameplay/Script.h>

class JumpJuice final : public engine::Script {
public:
    void OnUpdate(float dt) override {
        auto* t = Transform();
        if (t && dt > 0.0f) {
            const float vy = (t->position.y - m_lastY) / dt;
            m_lastY = t->position.y;
            if (m_wasFalling && vy > -0.5f) {              // was falling, now stopped → landed
                Camera().Shake(0.22f, 0.14f, 24.0f);
                Audio().PlayCue("Content/SFX/land.wav");
                Particles().Burst(10);                    // dust puff (Lesson 8)
            }
            m_wasFalling = vy < -3.0f;                     // remember a real fall
        }
        if (Input().KeyPressed(GLFW_KEY_SPACE))
            Audio().PlayCue("Content/SFX/jump.wav");
    }
private:
    float m_lastY = 0.0f; bool m_wasFalling = false;
};
Checkpoint Jumps have a whoosh, landings thud with a little screen shake and dust, and heights feel weighty.
Optional: a snappier feel Add a brief HitStop(0.04f) on a big landing, or a SetGlobalTimeDilation() flourish on the final jump. Little pauses read as impact.
8

Polish: audio & particles

You'll learn Attaching the particle systems and sounds your scripts already call, plus adaptive music.
  1. Your scripts already fire cues (coin/jump/land/hurt) and bursts (coin sparkle, crumble dust, landing dust, spike). Drop the WAVs at those paths and add particle systems to the matching prototypes so Particles().Burst(...) has something to emit.
  2. In the Particle Editor make: a Sparkle (coin), a Dust (crumble + land), and a Puff (spike). Attach each to its object.
  3. Add gentle ambient music on an empty Director object: Audio().LoadMusic("Content/Music/clouds.adaptive"); and, if you like, switch to a brighter state near the goal with Audio().SetMusicState("finale").
Checkpoint Coins sparkle, platforms puff dust, landings kick up dirt, and music carries the run. The platformer now has bounce and life.
9

The goal, win & ship

You'll learn Ending the level via GameMode and packaging a standalone build.
  1. Goal flag — add a Cylinder at the level's end, name it Goal, give it a Trigger collider, and attach a Goal script:
#include <engine/gameplay/Script.h>

class Goal final : public engine::Script {
public:
    void OnCreate() override { m_needCoins = GetFieldInt("coinsNeeded", 0); }
    void OnFixedUpdate(float) override {
        if (WasTriggerEntered(FindObject("Player"))) {
            if (Game()->Score() >= m_needCoins) {
                Game()->SetMessage("You reached the clouds!");
                Game()->Win();                              // HUD end screen
            } else {
                Game()->SetMessage("Collect more coins first!");
            }
        }
    }
private:
    int m_needCoins = 0;
};
  1. Enable Allow Restart in the scene's Game Mode settings, so the end screen offers R to replay.
  2. Playtest the whole run: jumps, moving/crumbling platforms, coins, spikes, falls, checkpoints, lives, and the goal.
  3. Package — export the runtime scene and build the standalone player. The cooker ships only reached assets. Distribute the player + cooked content.
Checkpoint — you shipped a platformer. A side-on 2.5D course with a jumping hero, moving and crumbling platforms, collectible coins, spikes and fall-death with checkpoints and lives, a HUD, jump juice, audio and particles, a goal flag with win/lose, and a standalone build.
