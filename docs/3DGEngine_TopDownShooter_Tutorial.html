A hands-on 3DGEngine tutorial

Arena Assault

Build a twin-stick top-down shooter — and learn the engine while you do it.

Nine lessons: an overhead arena, a twin-stick hero that moves and aims independently, bullets you spawn and that deal damage, waves of chasing enemies, health and score, a HUD, sound and particle punch, and game-over/restart with a packaged build. Every lesson names the engine system it teaches. Print to PDF with Ctrl+P → Save as PDF (A4).

What you'll build

A survival arena: move with WASD, aim/fire with the arrow keys (classic twin-stick), blast waves of enemies that path toward you, watch your health, rack up a score, and restart on death — then ship it as a standalone.

Lessons

  2. The arena & overhead camera — scenes, lighting, isometric controller
  3. Twin-stick movement & aim — scripting, input, facing

  5. Enemies & waves — nav agents, timers, spawners
  6. Health, damage & score — Health, contact damage, GameMode

Assets You can build this entirely from the editor's primitive meshes: a capsule for the player, capsules/cubes for enemies, a small sphere for bullets, a plane for the floor. Real art is optional — swap it in later. A few short WAVs (shoot, hit, explode) add a lot of punch.
1

Set up the project & import

You'll learn Projects (with isolated scripts) and importing — or how to work purely from primitives.
  1. File → New Project, name it ArenaAssault. It gets a Content folder and an empty script set of its own.
  2. Optional: drag art onto the window and use the Import dialog (models auto-detect skeletal vs static; textures get sRGB/Smooth). For this tutorial the built-in primitives are enough — capsule = player/enemies, sphere = bullet, plane = floor.
  3. Drop a few short WAVs into Content/SFX/ (shoot.wav, hit.wav, explode.wav) so the audio lines later just work.
Checkpoint A fresh ArenaAssault project is open.
2

The arena & overhead camera

You'll learn Building a scene, and the Isometric Player Controller that gives you a fixed overhead camera with camera-relative WASD movement — perfect for top-down.
  1. Floor — add a Plane, scale it ~40×40, give it a material and a Static Collider (Physics Setup → Static Collider).
  2. Walls — ring the arena with four Cubes scaled into walls; add Static Colliders so nothing escapes.
  3. Player — add a Capsule, name it Player. Give it a Capsule Collider and a Player Controller (Inspector → + Add Component → Player Controller), and set Camera Mode = Isometric. Tune Isometric Distance, Yaw, and Pitch for a comfortable overhead angle (e.g. pitch ≈ −60°).
  4. Add a Light (Directional) as the sun and set the sky/environment for ambient.
  5. Add a PlayerStart and press Play. The camera sits overhead; WASD moves the player relative to the screen, and the camera follows.
Checkpoint An overhead view of the arena with a capsule you can drive around with WASD.
Why Isometric? Isometric mode gives a fixed camera angle and screen-relative movement, so "up" on the keyboard always moves the player "up" on screen — exactly what a top-down game wants. The player's body faces its movement direction; aiming will be independent (next lesson).
3

Twin-stick movement & aim

You'll learn Reading input in a script to add an independent aim axis on top of the controller's movement — the heart of a twin-stick shooter.

Movement is already handled by the Isometric Player Controller (WASD). We add a script that reads the arrow keys as an aim direction and (next lesson) fires along it. Body faces where you move; bullets go where you aim.

  1. Select Player → Inspector → + Add Script → PlayerAim → Create + Attach.
  2. Write the aim axis (we wire up firing in Lesson 4):
#include <engine/gameplay/Script.h>
#include <glm/glm.hpp>

class PlayerAim final : public engine::Script {
public:
    void OnUpdate(float dt) override {
        glm::vec3 aim(0.0f);
        if (Input().KeyDown(GLFW_KEY_UP))    aim.z -= 1.0f;
        if (Input().KeyDown(GLFW_KEY_DOWN))  aim.z += 1.0f;
        if (Input().KeyDown(GLFW_KEY_LEFT))  aim.x -= 1.0f;
        if (Input().KeyDown(GLFW_KEY_RIGHT)) aim.x += 1.0f;

        m_firing = glm::length(aim) > 0.1f;
        if (m_firing) m_aim = glm::normalize(aim);   // keep the last aim direction
        // (firing added next lesson)
    }
protected:
    glm::vec3 m_aim{0.0f, 0.0f, -1.0f};   // where the gun points
    bool      m_firing = false;
};
Checkpoint The code compiles and attaches (Compile Scripts, Play). It doesn't do anything visible yet — the aim direction is just being tracked, ready to shoot.
Movement axis note Here "up" on screen is −Z and right is +X, matching the Isometric camera's default orientation. If your camera yaw is rotated, rotate the aim vector by the same yaw so arrows still map to screen directions.
4

Shooting

You'll learn Spawning objects at runtime, moving them with velocity, detecting hits with triggers, and giving them a lifetime — a complete projectile.

4a. The bullet prototype

  1. Add a small Sphere, name it Bullet. Give it: a Trigger collider (Physics Setup → Trigger), a Linear Velocity component (+ Add Component → Linear Velocity — this makes the runtime move it), and a bright emissive material.
  2. Add a Bullet script to it. It damages the first enemy it overlaps and self-destructs after a short life:
#include <engine/gameplay/Script.h>

class Bullet final : public engine::Script {
public:
    void OnCreate() override {
        Delay(1.5f, [this]{ DestroySelf(); });          // lifetime, so strays vanish
    }
    void OnFixedUpdate(float) override {                // overlap tests on the fixed step
        engine::ecs::Entity target = engine::ecs::kNull;
        Registry()->view<Health, engine::ecs::RuntimeName>().each(
            [&](engine::ecs::Entity e, Health& h, engine::ecs::RuntimeName& n) {
                if (target == engine::ecs::kNull && n.value != "Player"
                    && h.alive && IsTriggerTouching(e))
                    target = e;                          // first live non-player we're touching
            });
        if (target != engine::ecs::kNull) {
            if (auto* h = Registry()->TryGet<Health>(target)) h->Damage(m_damage);
            Particles().Burst(10);                       // impact spark
            DestroySelf();
        }
    }
private:
    float m_damage = 34.0f;
};
  1. Turn the Bullet into a prefab (right-click → Create Prefab → Bullet.3dgprefab) or just keep it as a named prototype in the scene — either way SpawnFromObject("Bullet",…) clones it. Move the prototype off-screen (or disable it) so the loose one isn't in play.

4b. Fire from the player

Extend PlayerAim to spawn a bullet along the aim vector on a fixed cadence:

    void OnUpdate(float dt) override {
        glm::vec3 aim(0.0f);
        if (Input().KeyDown(GLFW_KEY_UP))    aim.z -= 1.0f;
        if (Input().KeyDown(GLFW_KEY_DOWN))  aim.z += 1.0f;
        if (Input().KeyDown(GLFW_KEY_LEFT))  aim.x -= 1.0f;
        if (Input().KeyDown(GLFW_KEY_RIGHT)) aim.x += 1.0f;
        m_firing = glm::length(aim) > 0.1f;
        if (m_firing) m_aim = glm::normalize(aim);

        m_cooldown -= dt;
        if (m_firing && m_cooldown <= 0.0f) { Fire(); m_cooldown = m_fireRate; }
    }
private:
    void Fire() {
        auto* t = Transform(); if (!t) return;
        const glm::vec3 muzzle = t->position + m_aim * 0.8f + glm::vec3(0, 0.8f, 0);
        engine::ecs::Entity b = SpawnFromObject("Bullet", muzzle);
        if (auto* v = Registry()->TryGet<engine::ecs::LinearVelocity>(b))
            v->velocity = m_aim * m_bulletSpeed;
        Audio().PlayCue("Content/SFX/shoot.wav");
        Particles().Burst(6);                            // muzzle flash on the player
    }
    float m_cooldown = 0.0f, m_fireRate = 0.14f, m_bulletSpeed = 26.0f;
Checkpoint Hold an arrow key and a stream of glowing bullets fires that way while WASD moves you independently. (Nothing dies yet — enemies arrive next.) If bullets don't move, confirm the Bullet prototype has an enabled Linear Velocity component.
Fast bullets & tunnelling Trigger overlap can miss very fast, thin targets. Keep bullet speed moderate, make enemies not razor-thin, or (advanced) sweep a short raycast along the bullet's motion each fixed step for hit-scan accuracy.
5

Enemies & waves

You'll learn Nav Agents that chase a named target, and a spawner that uses timers to send escalating waves at the player.

5a. The enemy prototype

  1. Bake nav: Navigation preview → set bounds over the floor → Build.
  2. Add a Capsule, name it Enemy. Give it a Capsule Collider, a Health (e.g. 60), and a Nav Agent with Chase Target = "Player", a Speed of ~3, and a Repath Interval ~0.4s. It will path straight to the player.
  3. Add an Enemy script for contact damage and death rewards:
#include <engine/gameplay/Script.h>

class Enemy final : public engine::Script {
public:
    void OnFixedUpdate(float dt) override {
        if (auto* h = TryGet<Health>(); h && !h->alive) { Die(); return; }

        m_hitCooldown -= dt;
        auto* me = Transform();
        auto* pt = FindTransform("Player");
        if (me && pt && glm::length(pt->position - me->position) < 1.5f
            && m_hitCooldown <= 0.0f) {
            if (auto* ph = TryGet<Health>(FindObject("Player"))) ph->Damage(12.0f);
            m_hitCooldown = 0.6f;                          // damage tick
        }
    }
private:
    void Die() {
        if (m_dead) return; m_dead = true;
        Game()->AddScore(10);
        Particles().Burst(30);
        Audio().PlayCue("Content/SFX/explode.wav");
        DestroySelf();
    }
    float m_hitCooldown = 0.0f; bool m_dead = false;
};
  1. Make Enemy a prefab/prototype and move the loose one off-screen.

5b. The wave spawner

Add an empty object Director with a WaveSpawner script. It rings the arena with enemies, ramping each wave:

#include <engine/gameplay/Script.h>
#include <cmath>
#include <cstdlib>

class WaveSpawner final : public engine::Script {
public:
    void OnCreate() override { BeginWave(); }

    void OnUpdate(float dt) override {
        m_spawnTimer -= dt;
        if (m_left > 0 && m_spawnTimer <= 0.0f) {
            SpawnOne();  --m_left;  m_spawnTimer = m_interval;
        }
        m_waveTimer -= dt;
        if (m_left == 0 && m_waveTimer <= 0.0f) BeginWave();   // next wave after a breather
    }
private:
    void BeginWave() {
        ++m_wave;
        m_left     = 4 + m_wave * 2;                       // more each wave
        m_interval = std::max(0.25f, 0.8f - m_wave * 0.05f);
        m_waveTimer = m_left * m_interval + 6.0f;
        Game()->SetMessage("Wave " + std::to_string(m_wave));
    }
    void SpawnOne() {
        const float a = (float)std::rand() / RAND_MAX * 6.2831853f;
        SpawnFromObject("Enemy", glm::vec3(std::cos(a) * 16.0f, 0.0f, std::sin(a) * 16.0f));
    }
    int m_wave = 0, m_left = 0;
    float m_spawnTimer = 0.0f, m_interval = 0.8f, m_waveTimer = 0.0f;
};
Checkpoint Waves of capsules stream in from the arena edge and path toward you; your bullets kill them (Health hits 0 → they explode and score). If they don't move, re-check the navmesh bake and the Nav Agent's Chase Target = "Player".
6

Health, damage & score

You'll learn Giving the player Health, taking contact damage, and ending the run on death via GameMode.
  1. Select Player → add a Health component (e.g. 100). The enemy script already calls Damage(12) on the object named "Player", so contact now hurts.
  2. Add a PlayerState script to the Player that ends the run at zero HP and tracks a best score:
#include <engine/gameplay/Script.h>

class PlayerState final : public engine::Script {
public:
    void OnUpdate(float) override {
        if (m_over) return;
        if (auto* h = TryGet<Health>(); h && !h->alive) {
            m_over = true;
            SaveInt("bestScore", std::max(GetSavedInt("bestScore"), Game()->Score()));
            Game()->SetMessage("You were overrun!");
            Game()->Lose();                                // GameMode → end screen (Lesson 9)
        }
    }
private:
    bool m_over = false;
};
Checkpoint Let an enemy touch you a few times — your HP falls and the run ends when it hits 0. Score climbs as you kill enemies (each enemy adds 10 via its Die()).
Score already works Because each enemy calls Game()->AddScore(10) on death, the shared GameMode score is live — the HUD (next) reads it with no extra code.
7

The HUD

You'll learn Binding UI widgets to runtime values so the display updates itself.
  1. HUD editor → add a Health bar bound to the player's Health (healthFraction).
  2. Add a text widget Score: {} bound to score (from GameMode).
  3. Add a centered message text bound to gamemessage — this shows "Wave N" from the spawner and "You were overrun!" on death.
  4. Save Game.hud and reference it from the scene.
Checkpoint Health bar drains under fire, score counts kills, and the wave banner flashes each new wave — all driven by gameplay, no wiring code.
8

Polish: audio & particles

You'll learn Layering sound cues and particle bursts you've already hooked, plus adaptive music that reacts to pressure.
  1. Your scripts already fire cues (shoot.wav on Fire, explode.wav on enemy death) and particle bursts (muzzle on Fire, impact on Bullet hit, explosion on enemy death). Drop the WAVs at those paths and add particle systems to the Player / Bullet / Enemy prototypes so Particles().Burst(...) has something to play.
  2. Author quick systems in the Particle Editor: a bright Muzzle (short cone), an Impact (sparks), and an Explosion (burst + smoke). Attach each to the matching prototype.
  3. Add ambient music that intensifies with the wave — put this on Director:
void OnCreate() override { Audio().LoadMusic("Content/Music/arena.adaptive"); }
// inside BeginWave():   Audio().SetMusicState(m_wave >= 4 ? "intense" : "steady");
Checkpoint Shooting cracks, hits spark, enemies pop with a boom, and the music lifts as waves escalate. The arena now feels dangerous.
9

Game over, restart & ship

You'll learn The GameMode end screen with restart, and packaging a standalone build.
  1. You already call Game()->Lose() on death. In the scene's Game Mode settings, enable Allow Restart. The runtime then shows a centered GAME OVER with your score and "Press R to restart" — R reloads the arena.
  2. Optionally add a win condition (survive N waves): in WaveSpawner::BeginWave, if (m_wave > GetFieldInt("wavesToWin", 8)) Game()->Win();.
  3. Playtest the full loop: waves ramp, health matters, score climbs, death ends the run, R restarts, the best score persists (bestScore).
  4. Package — export the runtime scene and build the standalone player. The AssetCooker ships only the assets the scene reaches. Distribute the player executable + the cooked content.
Checkpoint — you shipped a shooter. An overhead arena, twin-stick movement + aim, spawned projectiles with real hit detection, escalating waves of pathing enemies, health/score/HUD, audio and particle feedback, game-over with restart, and a standalone build.
