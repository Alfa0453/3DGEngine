Setting Up a Fully Animated Character

Building a playable character from a skeletal model and separate FBX clips — Idle, Walk and Run — that blends automatically in Play mode.

Applies to the Character Editor, Model Transform, Locomotion graph and Play mode · low-poly / Mixamo-style rigs

What you'll build

A reusable character asset (.3dgcharacter) that carries the visible mesh, three merged FBX animations, a capsule collider, a player controller, and a one-dimensional locomotion blend space. Once placed in a scene and set as the player, it walks and runs under keyboard control while the animation cross-fades Idle → Walk → Run based on how fast it is moving.

The core idea. Your model and your animations live in separate FBX files. The Character Editor merges each animation onto the model by bone name, so a shared rig (e.g. Mixamo) lets one skeleton play many clips. A 1D blend space keyed on a single Speed value chooses between Idle, Walk and Run — and in Play mode the engine drives that Speed for you from the character's movement.

Before you start — assets you need

  • One skeletal model — the character mesh with its skeleton (FBX/glTF). This is the "base" rig.
  • Three animation files — separate FBX exports of Idle, Walk and Run that use the same skeleton / bone names as the model.
Tip — Mixamo workflow Upload your rig to Mixamo, then download the Idle, Walk and Run animations as FBX, "Without Skin", keeping identical bone names. They'll merge cleanly onto your model. In-place variants are ideal; if only "in motion" versions exist, use Strip Root Motion (below) to keep the character from sliding.

Put the files in the project's Content folder

Copy the model and the three animation FBX files into your project, e.g.:

FirstGame/Content/Assets/Characters/  (model + Idle.fbx, Walk.fbx, Run.fbx)

Use the Assets panel → Import file if they aren't there yet, then Refresh. Only assets inside Content appear in the editor's searchable pickers.

Step-by-step: create the character asset

Open Panels → Character Editor (or the Character Editor button). Work through the component tabs down the left side. Nothing here touches the scene until you add the character to it, so you can iterate freely.

  1. Mesh tab — pick the model. Set Skeletal Model to your character mesh, and optionally a Material (a .3dgmat from the Material Maker). The live preview loads the rig in its bind (T‑)pose.
  2. Mesh tab — add the animation sources. Under Animation Sources (separate files), add one row per clip:
    • File → pick Idle.fbx; Clip Name → Idle
    • Add Walk.fbx → Walk, and tick Strip Root Motion
    • Add Run.fbx → Run, and tick Strip Root Motion
    Each file is merged onto the model by bone name. Naming them exactly Idle / Walk / Run lets the one-click locomotion builder wire them up automatically.
  3. Mesh tab — Model Transform & facing. Scroll to Model Transform. If the rig imports lying down (Z‑up), click Stand up (Z-up) (sets Model Rot = -90, 0, 0). Then rotate Model Rot Y (e.g. 180) until the mesh's face points along the cyan forward arrow. This is render-only — the collider stays upright.
  4. Collision tab. Keep Collider Enabled with shape Capsule. Set Radius and Half Height to wrap the body (e.g. 0.4 / 0.9). Layer stays Player.
  5. Movement tab. Enable the Player Controller. Set Walk Speed and Run Speed (e.g. 3 and 6). These are the speeds that will drive the animation blend, so remember them for Step 7.
Why Strip Root Motion Walk/Run clips often bake forward travel into the root bone. Since the player controller moves the capsule itself, leaving root motion in makes the mesh "double-move" and slide. Stripping it keeps the feet planted relative to the body while the controller does the travelling.

Step-by-step: build the locomotion state machine

Switch to the Animation tab. This is where Idle/Walk/Run become a single blendable state.

  1. Create the blend space. With your three sources named Idle/Walk/Run, click Create 1D Locomotion. The editor builds a Locomotion state: a one-dimensional blend space driven by the Speed parameter, with Idle at 0, Walk at a mid speed and Run at the top. Synchronize Animation Cycles keeps the feet in phase as it blends.
  2. Match the blend to your speeds. Open the Locomotion state and check the blend samples. The Speed values where Walk and Run sit should line up with the Walk/Run Speed you set in the Movement tab (Step 5). Rule of thumb: Idle → 0, Walk → walkSpeed, Run → runSpeed.
  3. Preview it. In the preview, drag the Speed parameter (or the Live Graph Preview) from 0 upward and watch the character ease from Idle into Walk into Run. Use Play/Pause and orbit to inspect foot contact.
  4. Save the character. Use the panel's menu to Save the .3dgcharacter asset into Content/Assets/Characters.
Prefer explicit states? Use the graph instead Rather than one blend space, you can author three separate States (Idle, Walk, Run) plus Transitions between them that compare the Speed parameter against thresholds (e.g. Idle→Walk when Speed > 0.1, Walk→Run when Speed > 4, and the reverse). Add a Speed float under Parameters first. The blend space is simpler and smoother for pure locomotion; explicit states give you more control for combat or one-shots.

How the states are driven in Play mode

You never set Speed by hand at runtime. When the character is the active player, the engine updates its animation parameters every frame from the controller's movement:

ParameterTypeDriven from
SpeedfloatMove input × (sprinting ? Run Speed : Walk Speed) — the locomotion driver
DirectionfloatStrafe angle in degrees (for 2D/directional blends)
IsMoving / IsStoppingboolWhether Speed is above / dropping below the move threshold
IsGrounded / IsFallingboolCharacter controller ground state
VerticalSpeedfloatVertical velocity (jump / fall)
Acceleration / Deceleration / TurnRatefloatRate of change of speed and look yaw

For basic Idle/Walk/Run you only need Speed — the rest are there for richer graphs (starts/stops, jumps, strafing). AI characters get the same Speed driven from their nav velocity, so the identical graph works for NPCs.

Step-by-step: place it and make it the player

  1. Add to the scene. With a scene open, drag the .3dgcharacter from the Assets panel into the viewport, or use Add to Scene in the Character Editor. It spawns auto-sized (~1.8 units tall) standing on the drop point.
  2. Check the forward arrow. The selected character shows a cyan ground arrow for its forward (‑Z). Confirm the mesh's face points along it; if not, adjust Model Rot in the Inspector's Model Transform (or fix it once in the Character Editor so every instance is correct).
  3. Confirm it's the player. Because the character has Player Controller enabled, it becomes the controlled player when you enter Play (the first player-controller object in the scene is chosen). No separate PlayerStart wiring is required.
  4. Give it ground. Make sure there's a floor/terrain with a collider under it so the capsule has something to stand and walk on.

Play it

  1. Enter Play mode. The camera attaches to the character (third-person by default).
  2. Move. W A S D walk, Shift sprint (Run), Space jump, Mouse look. As you accelerate, the character blends Idle→Walk→Run; releasing the keys eases it back to Idle.
  3. Verify. Feet should track the ground without sliding, the body should face its travel direction, and the shadow should sit on the floor.

Troubleshooting

SymptomCause & fix
Character stays in T‑pose / never animatesClip names don't match, or no locomotion was built. Re-check the source Clip Names and click Create 1D Locomotion. Ensure the model actually has bones matching the animation files.
Feet slide across the groundRoot motion still baked in. Tick Strip Root Motion on the Walk and Run sources.
Only Idle plays, Walk/Run never triggerBlend-space speeds don't match movement speeds. Align the blend samples' Speed with the Movement tab's Walk/Run Speed.
Mesh faces backward / sidewaysRotate Model Rot Y by 180° (or ±90°) until the face aligns with the cyan forward arrow.
Mesh lies down / faces the camera on spawnZ‑up rig. Use Stand up (Z-up), then adjust yaw. This is render-only; the capsule stays upright.
Character is huge or tinySpawns auto-scaled to ~1.8 units; adjust the object Scale in the Inspector if your world uses a different unit scale.
Doesn't move in PlayPlayer Controller not enabled on the character, or no ground collider beneath it.
Character sinks / floats above the floorTune the capsule Half Height / Radius so the capsule bottom meets the feet.
Reuse Because all of this lives in the .3dgcharacter asset, you can drop the same character into any scene and it arrives fully rigged, collided, controllable and animated. Duplicate the asset and swap the model/clips to spin up variants (enemies, NPCs) that share the graph.
