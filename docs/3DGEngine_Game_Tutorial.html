A hands-on 3DGEngine tutorial

Coin Rush

Build a complete little game — and learn the engine while you do it.

Over eleven short lessons you will make a third-person arena game: collect the coins before a hunting enemy catches you, with animation, physics, a HUD, audio, checkpoints, and a shippable build. Every lesson names the engine system it teaches. Print to PDF with Ctrl+P → Save as PDF (A4).

What you'll build

A playable loop: a controllable character with real locomotion, coins that score, a HUD, an AI enemy that sees and hears you, combat with ragdoll death, sound and particle polish, checkpoints you can save/load, and win/lose with a packaged executable.

Before you start You need the editor built and a few source assets: a rigged character FBX with idle/walk/run takes (a Mixamo export works well), a coin mesh, a couple of prop meshes, some textures, and a few short WAV sounds. No assets? Use the editor's primitive meshes for everything and a capsule as the "character" — the lessons still work; you just skip the animation import in Lesson 3.
1

Set up the project & import assets

You'll learn How projects work, how each project's scripts are isolated, and how to import art with the drag-and-drop Import dialog.
  1. Open the editor. File → New Project. Pick a folder, name it CoinRush, and confirm. The editor creates a Content folder and an empty, isolated script set — nothing from other projects leaks in.
  2. Drag your source files (character FBX, coin/prop meshes, textures, WAVs) from Windows Explorer onto the editor window. The Import Settings dialog appears and scans each file's type.
  3. In the dialog: confirm the character imports as Skeletal Mesh (it shows e.g. "[Model] hero.fbx (skeleton, 1 mesh, 6 anim)"), the coin/props as Static Mesh, colour textures with sRGB on and any normal/roughness maps with sRGB off. Set the Target Folder, then Import.
  4. Check the Console — you'll see one line per imported asset. The Content Browser now shows them.
Checkpoint Your Content Browser lists the character, meshes, textures, and sounds. If a model came in as the wrong type, re-drop it and override the mode in the dialog.
No assets? Skip the drop step and use the built-in primitive meshes (cube, plane, sphere, capsule) throughout. Use a capsule as your "character" and revisit Lesson 3 later.
2

Build the arena

You'll learn Placing objects, materials, lighting, and giving geometry physics colliders so the player and AI can stand on and bump into it.
  1. Floor — add a Plane (or drag your floor mesh in). Scale it to ~30×30. In the Inspector assign a material (make one in the Material Maker first if you like), then + Add Component → Physics Setup → Static Collider so it's solid ground.
  2. Walls — add four Cubes around the edge, scale them into walls, and give each a Static Collider too, so nothing walks off the arena.
  3. Props — scatter a few meshes for cover. Props the enemy shouldn't see through need colliders; decorative ones don't.
  4. Sun — add a Light, set it to Directional, and aim it down at an angle. Set the scene's environment/sky for ambient fill so shadows aren't pitch black.
  5. Frame the camera and press Play briefly to confirm the arena renders and is lit, then stop.
Checkpoint A lit floor with walls and props. Selecting the floor and toggling Show Collider should outline its collision shape.
Match Collider to Scale If you resize an object after adding a collider, click Match Collider to Scale in the Inspector so the collision shape refits.
3

Make the player character

You'll learn The animation pipeline — clips → graph → character — and the Player Controller that gives you a moving, animated hero.

3a. Wrap your takes as clips

  1. Open the Clip Editor. Pick your character FBX as the source, choose the Idle take in the Clip dropdown, set Loop on, name it Idle, and Save Idle.3dgclip.
  2. Repeat for Walk and Run (loop on). Use the live preview to confirm each take plays.

3b. Build the locomotion graph

  1. Open the Graph Editor. Add Clip… and add Idle, Walk, Run.
  2. Add a Float parameter named Speed.
  3. Click Create 1D Locomotion — it makes a blend-space state (Idle at 0, Walk at ~1.5, Run at ~4) driven by Speed.
  4. Look at the Validation strip at the top. Clear any red items (unresolved clips) and yellow items (always-true transitions, undeclared parameters, dead ends). Save Locomotion.3dggraph.
Why validation matters A transition like Speed >= 0 is always true and would skip your idle on frame 1. The strip flags it; fix it to Speed > 0.1 or delete stray transitions.

3c. Assemble the character

  1. Open the Character Editor. Set the skeletal model + material.
  2. Under Animation Graph, reference Locomotion.3dggraph. The preview now plays Idle — drag the Speed slider to watch idle → walk → run.
  3. Set the capsule Collider to fit the body, and enable the Player Controller (Third Person). Optionally enable Foot IK so feet plant on the ground.
  4. Save Hero.3dgcharacter. Drag it into the scene, name it Player, and add a PlayerStart object so the runtime binds the camera and controls to it.
Checkpoint Press Play. WASD moves the hero; the mesh blends idle → walk → run as you speed up, and the camera follows in third person. If it T-poses, the graph's clips didn't resolve — re-check the clip names in the Graph Editor.
4

Your first script

You'll learn How native C++ scripts attach to objects and the four lifecycle callbacks — the foundation for all gameplay.
  1. Add an empty object, name it Spinner, and give it a small mesh.
  2. Inspector → + Add Script → name it Spinner → Create + Attach. The editor creates Content/Scripts/Spinner.h, registered for this project only.
  3. Open Spinner.h and make it rotate:
#include <engine/gameplay/Script.h>

class Spinner final : public engine::Script {
public:
    void OnCreate() override {
        m_speed = GetFieldFloat("spinSpeed", 90.0f);   // tune this in the Inspector
    }
    void OnUpdate(float dt) override {                  // per rendered frame
        if (auto* t = Transform())
            t->rotation = glm::rotate(t->rotation,
                              glm::radians(m_speed * dt), glm::vec3(0,1,0));
    }
private:
    float m_speed = 90.0f;
};
  1. Save, then Compile Scripts (the Script Editor button, or accept the prompt).
  2. Press Play — the Spinner rotates. Stop, change its spinSpeed field in the Inspector, Play again — no recompile needed for the value.
Checkpoint The object spins in Play. You just used OnCreate (read a field), OnUpdate (per-frame logic), Transform() (my components), and a designer-tunable field.
Update vs FixedUpdate Cosmetic/per-frame work goes in OnUpdate(dt). Anything touching physics/collision goes in OnFixedUpdate(dt), which runs at the fixed simulation step.
5

Coins & scoring

You'll learn Trigger volumes, reading the shared GameMode for score, and reusing objects with prefabs.
  1. Make one coin: add your coin mesh, name it Coin. Inspector → + Add Component → Physics Setup → Trigger (an overlap-only collider that never blocks movement). Size it a bit larger than the mesh so it's easy to grab.
  2. Make sure your Player object also has a collider (the character's capsule counts).
  3. Add a Coin script to the coin (+ Add Script → Coin → Create + Attach) and write it:
#include <engine/gameplay/Script.h>

class Coin final : public engine::Script {
public:
    void OnCreate() override { m_spin = GetFieldFloat("spinSpeed", 140.0f); }

    void OnUpdate(float dt) override {                     // pretty spin
        if (auto* t = Transform())
            t->rotation = glm::rotate(t->rotation,
                              glm::radians(m_spin*dt), glm::vec3(0,1,0));
    }
    void OnFixedUpdate(float) override {                  // collision happens on the fixed step
        if (WasTriggerEntered(FindObject("Player"))) {
            Game()->AddScore(1);                          // shared score → HUD later
            Audio().PlayCue("Content/SFX/coin.wav");      // will play once we add audio
            DestroySelf();                                // safe: queued, not immediate
        }
    }
private:
    float m_spin = 140.0f;
};
  1. Compile Scripts, Play, walk into the coin — it vanishes. (Watch the Console; the score is rising even though there's no HUD yet.)
  2. Make it a prefab: right-click the coin → Create Prefab → Coin.3dgprefab. Now drag that prefab into the arena a dozen times to place all your coins. Editing the prefab later updates every instance.
Checkpoint Multiple coins in the arena, each disappears on pickup, and the score climbs. You used a trigger, WasTriggerEntered, Game(), and a prefab.
6

The HUD

You'll learn How UI widgets bind to runtime values by name, so gameplay drives the display with no glue code.
  1. Open the HUD editor and add a text widget with the text Coins: {}. Bind it to the named value score — the {} is filled from GameMode's score automatically.
  2. Add a Health bar widget; it binds to the player's Health (healthFraction). (We add Health to the player in Lesson 8; the bar will read it then.)
  3. Add a centered message text bound to gamemessage — this shows your win/lose text later.
  4. Save Game.hud and reference it from the scene (scene settings → HUD).
Checkpoint Press Play — the coin counter updates live as you collect coins. No extra code: the widget reads score straight from GameMode.
Push your own values Beyond the built-ins (score, time, gamestate, gamemessage), you can drive custom HUD strings/floats from gameplay via the GameMode/HUD context — handy for timers or wave numbers.
7

The enemy

You'll learn Navigation baking and Nav Agents — an enemy that paths around the arena and chases you when it sees or hears you.
  1. Bake navigation: open the Navigation preview, set the bounds to cover the floor, and Build. You'll see the walkable navmesh polygons.
  2. Place another character (or a capsule) and name it Guard.
  3. Inspector → + Add Component → Nav Agent. Set: Speed ~3, a Reach Radius, a Repath Interval (~0.4s), a Vision Range and half-angle, a Hearing Range, Team = 2, and turn on Auto-target (it will pick the nearest enemy of a different non-zero team — set the Player's Nav Agent, or its team tag, to team 1).
  4. Give the Guard Health (we'll use it in Lesson 8).
  5. Press Play. The Guard patrols; when it sees you (in its vision cone with clear line-of-sight) or hears you running past, it switches to Chase and paths toward you, then Searches your last-known spot when it loses you.
Checkpoint The Guard reacts to you: sprint near it and watch it give chase; break line-of-sight behind a prop and watch it search where it last saw you.
Hearing Moving fast emits footstep noise that scales with speed; taking or dealing damage emits a loud combat noise. Sneak slowly to stay quiet.
8

Combat & ragdoll

You'll learn One-shot action animations, animation notify events, applying damage through Health, and ragdoll death.

8a. An attack action

  1. In the Clip Editor wrap your attack take as an Action Clip named Attack (Action Clip = one-shot, plays over locomotion). Author a notify event named hit on the frame the swing connects.
  2. Add a PlayerCombat script to the Player:
#include <engine/gameplay/Script.h>

class PlayerCombat final : public engine::Script {
public:
    void OnUpdate(float) override {
        if (Input().KeyPressed(GLFW_KEY_SPACE))
            Anim().PlayAction("Attack");                 // one-shot montage

        if (WasAnimationEvent("hit")) {                  // fires on the authored keyframe
            if (ecs::Entity guard = FindObject("Guard"); guard != engine::ecs::kNull) {
                auto* gt = Registry()->TryGet<ecs::Transform>(guard);
                auto* pt = Transform();
                if (gt && pt && glm::length(gt->position - pt->position) < 2.2f)
                    if (auto* hp = Registry()->TryGet<Health>(guard))
                        hp->Damage(50.0f);               // in range → hit
            }
        }
    }
};
Why a notify event? Firing damage on the hit frame (not on the key-press) makes the swing feel connected — the hit lands exactly when the animation says so.

8b. Ragdoll on death

  1. Select the Guard → Inspector → Health → Ragdoll On Death. Tune Mass, Physics Bodies, Body Thickness, damping, and Death Impulse.
  2. Play, land two hits on the Guard — at zero HP its animation stops and it collapses into connected physics bodies.
Checkpoint Space swings; a close swing damages the Guard on the hit frame; two hits drop it into a ragdoll. Give the Guard its own attack that damages the Player's Health the same way for a two-way fight.
9

Polish: audio & particles

You'll learn Firing sound cues and driving particle systems from scripts, and using animation events so effects land on the exact frame.

9a. Audio

  1. You already call Audio().PlayCue("Content/SFX/coin.wav") in the Coin script — drop a coin WAV at that path and it plays on pickup.
  2. Add ambient music: put a script on an empty object that loads and plays it, switching mood when the Guard is chasing:
void OnCreate() override { Audio().LoadMusic("Content/Music/level.adaptive"); }
void OnUpdate(float) override {
    Audio().SetMusicState(guardChasing ? "combat" : "explore");  // beat-synced switch
}
  1. Add a footstep cue on the character's walk clip: author a footstep notify and play a cue when it fires (in a script on the Player): if (WasAnimationEvent("footstep")) Audio().PlayCue("Content/SFX/step.wav");

9b. Particles

  1. In the Particle Editor start from a preset (e.g. Sparkle), tune it, and save Pickup.particle. Add it to the Coin prefab.
  2. Burst it on pickup — add one line to the Coin's pickup block: Particles().Burst(24); right before DestroySelf().
  3. For the attack, burst an impact effect on the hit event: if (WasAnimationEvent("hit")) Particles().Burst(30);
Checkpoint Coins sparkle and click on pickup, footsteps and hits have sound, and music shifts to a combat cue when the Guard chases. The game now feels alive.
10

Checkpoints & saving

You'll learn The save system — quick checkpoints, typed persistent values, and full save slots that restore the whole world.
  1. Place a trigger volume named Checkpoint partway through the arena. Add a script that saves when the Player enters it:
void OnFixedUpdate(float) override {
    if (WasTriggerEntered(FindObject("Player"))) {
        SaveGameToSlot(0, "Checkpoint");     // captures Transforms, Health, velocities, etc.
        Game()->SetMessage("Checkpoint!");   // brief HUD note
    }
}
  1. Make death load the last save. In a PlayerHealth watcher script:
void OnUpdate(float) override {
    if (auto* h = TryGet<Health>(); h && !h->alive) {
        LoadGameFromSlot(0);                 // reloads the scene + restores the snapshot
    }
}
  1. Persist a running best-coins value with the typed store: SaveInt("bestCoins", std::max(GetSavedInt("bestCoins"), Game()->Score()));
Checkpoint Cross the checkpoint, die on purpose — the world reloads to the saved state. In a packaged build the player can also F5 quick-save and F9 open the load menu.
11

Win, lose & ship it

You'll learn Ending the game through GameMode, and packaging a standalone build that ships only the assets it uses.
  1. Win condition — on an empty GameRules object, end the game when every coin is collected:
void OnCreate() override { m_toWin = GetFieldInt("coinsToWin", 12); }
void OnUpdate(float) override {
    if (Game()->Score() >= m_toWin) Game()->Win();          // HUD shows VICTORY
    // lose if the player died (its Health went to 0 and it wasn't checkpoint-restored)
}
int m_toWin = 12;
  1. Lose condition — if you didn't add checkpoint-reload, call Game()->Lose() on player death instead; the HUD end screen reads gamestate/gamemessage.
  2. Playtest the whole loop — collect all coins to win; get caught/killed to lose; verify the HUD, audio, and saves along the way.
  3. Package — export the runtime scene and build the standalone player. The AssetCooker walks the scene's dependencies and copies only the assets it reaches, so unused imports never ship. Distribute the player executable plus the cooked content folder.
Checkpoint — you shipped a game. A lit arena, an animated third-person hero (with optional foot IK), spinning coins that score to a live HUD, a Guard that sees and hears and chases and ragdolls, combat with frame-accurate hits, audio and particles, checkpoints and an in-game save menu, win/lose, and a standalone build.
